# 小说创作辅助平台 — 需求分档（优先级评估与排期映射）

> 版本：v1.0　　依据：《需求分析报告（粗略版）》+《详细设计文档 v1.0》
> 用途：开发排期、范围控制、砍需求时的决策依据

---

## 一、分档方法与标准

### 1.1 分档维度

每个需求从三个维度打分（1~5），得出优先级：

| 维度 | 含义 | 评估问题 |
|---|---|---|
| **用户价值 V** | 对目标用户（网文作者）的痛点缓解程度 | 没有它用户会不会走？ |
| **实现成本 C** | 开发人日 + AI 成本 + 技术风险 | 详细设计文档中该模块的实现难度 |
| **依赖风险 R** | 被其他功能依赖的程度 + 技术不确定性 | 是不是别人的前置？翻车概率高不高？ |

### 1.2 档位定义

| 档位 | 名称 | 定义 | 范围策略 |
|---|---|---|---|
| **P0** | 必做（MVP 门槛） | 没有它产品不成立：用户注册→建作品→写→存→导出的最小闭环 | 任何情况下不砍 |
| **P1** | 核心价值 | 产品差异化的主要来源，决定用户是否愿意持续使用/付费 | 可延期，不可砍 |
| **P2** | 重要增强 | 显著提升体验，但有替代方案或低频使用 | 档期紧时可砍 |
| **P3** | 锦上添花 | 有更好，没有不影响核心体验 | 默认不做，有余力再说 |
| **X** | 暂缓/不做 | 技术不成熟、价值存疑或风险大于收益 | 移出路线图，单独评审 |

### 1.3 核心判断逻辑（一句话版）

> **先用 P0 证明"这是个能用的写作工具"，再用 P1 证明"这是个别处没有的写作工具"。**

## 三、价值-成本象限（决策视图）

```
高价值 │
       │  ①续写/润色      ②章节摘要+曲线      ③自动保存
       │  ④版本历史       ⑤拆书报告+导出MD    ⑥人物卡/设定/大纲
       │
       │  ⑦关系图(高风险)  ⑧一致性检查(高风险)  ⑨导出DOCX/EPUB
       │  ⑩伏笔管理        ⑪卡文建议
       │
───────┼───────────────────────────────────────────
       │  ⑫专注模式  ⑬灵感碎片  ⑭起名  ⑮关键词
低价值 │  ⑯写作时长
       └───────────────────────────────────────────
        低成本                    高成本
```

**象限结论**：
- **优先收割区（左上）**：①~⑥，全部 P0/P1，构成产品主体；
- **谨慎投入区（右上）**：⑦⑧ 价值高但技术风险大，**必须带"置信度/人工确认"降级方案才允许排期**；
- **顺手做区（左下）**：有空就塞，不单独排期；
- **右下**：原则上本期不做。

## 四、排期映射（四期计划修订版）

> 假设单人全栈或 1 后端 + 1 前端，每期 4~6 周。

### 第一期（MVP）——"能写、不丢、能拿走"

**目标**：最小创作闭环 + 拆书入口跑通，验证用户愿意上传书。

| 内容 | 对应档位 |
|---|---|
| 注册登录、作品/卷/章管理、目录树 | P0 (2.1/2.2/2.3) |
| 富文本编辑器 + 自动保存 | P0 (2.4/2.5) |
| 导出 TXT（整本/按卷） | P0 (2.11) |
| 上传原书 + 自动分章 + 章节浏览 | P0 (1.1/1.2/1.12) |
| 任务框架 + AI 网关 + 缓存/额度 | P0 (3.0/1.13/N4) |
| 每日备份 + 上传安全校验 | P0 (N1/N2/N3) |

**验收**：用户全流程无中断；100 万字书 5 分钟内完成分章入库；服务端不丢稿。

### 第二期（核心价值）——"拆得动、写得快"

**目标**：拆书报告 + AI 辅助双引擎，形成差异化。

| 内容 | 对应档位 |
|---|---|
| 章节摘要 + 情绪曲线 + 爽点标记 | P1 (1.3/1.4/1.5) |
| 人物统计 + 报告页 + 导出 MD | P1 (1.6/1.10) |
| SSE 任务进度 | P1 (N5) |
| 人物卡 / 设定集 / 大纲管理 | P1 (2.15/2.16/2.17) |
| AI 续写（含大纲人物注入）+ 润色改写 | P1 (3.1/3.2) |
| 版本历史 + 回滚、字数统计 + 码字目标 | P1 (2.7/2.8) |
| 断网草稿恢复 | P1 (2.6) |

**验收**：百万字书全量分析成本 ≤¥6 且可缓存复用；续写采纳率（采纳/生成次数）≥30%（埋点验证）。

### 第三期（增强与闭环）——"管得住、连得起来"

| 内容 | 对应档位 |
|---|---|
| 拆书联动：参考曲线浮层 + 桥段模板库 | P2 (3.9) |
| 伏笔管理（半自动）+ 久未出场提醒 | P2 (3.7/3.8) |
| 一致性检查建议（置信度展示，不做强断言） | P2 (3.6) |
| 人物关系图（AI 推断 + 人工编辑） | P2 (1.8) |
| 节奏分析 + 关键词 | P2 (1.7/1.9) |
| 导出 DOCX/EPUB/PDF | P2 (2.12/1.11) |
| 卡文分支建议 + 起名助手 | P2 (3.3/3.4) |
| 查找替换、专注模式、敏感词提示 | P2 (2.10/2.9/2.14) |
| 监控告警 + 多模型界面配置 | P2 (N8/N9) |

### 第四期（择机）—— 剩余 P3 按反馈挑做

灵感碎片增强、对话生成、导出模板、写作时长统计、移动端。

### X 档处理

| 条目 | 处置 |
|---|---|
| 情节线主支线识别（1.14） | 不做；待 LLM 能力演进后单独评审 |
| 抄袭检测（3.10） | 不做；敏感且低频 |
| 移动端适配（N10） | 明确声明 PC 优先；仅保证报告页只读可窄屏查看 |

## 五、砍需求的决策规则（范围蔓延时使用）

当档期不足需要砍范围时，按以下顺序处理：

1. **先砍 P3**：无任何讨论成本；
2. **再砍 P2 中的"右下近邻"**：关键词、灵感碎片、起名、专注模式；
3. **P2 中的高风险项单独评审**：关系图、一致性检查——若降级方案（置信度+人工确认）在当期做不完，宁可整体后移，**不上线一个会误导用户的"智能"功能**；
4. **P1 可延期不可砍**：若 P1 某条目被砍，说明本期目标本身不成立，应重新评估分期而不是硬砍；
5. **P0 任何情况下不动**；若 P0 做不完，砍的是 P0 内部的实现规格（如编辑器先单模式），不是条目本身。

## 六、验证指标（每期上线后回答的问题）

| 期 | 核心假设 | 验证指标 |
|---|---|---|
| 一期 | 作者愿意把书传上来拆 | 上传完成率 ≥70%（完成上传/点击上传） |

| 三期 | 联动与设定管理形成使用习惯 | 周活跃作者中 ≥40% 维护人物卡/大纲；伏笔功能使用率 |
| 四期 | （视前三期数据决定方向） | —— |
